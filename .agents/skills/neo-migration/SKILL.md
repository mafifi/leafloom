# NEO migration

1. Read the feature and full scenario clauses in `docs/migration/feature-inventory.json` and its pinned `tests/reference/neo` source anchors.
2. Read the historical action/assertion mapping; treat it as a source map, never a current candidate pass.
3. Identify original Electron, candidate browser and native Tauri duties. Keep native Electron operations inside the reference adapter.
4. Build equivalent private synthetic fixtures. Initial state may be injected; post-action results must come from actual author operations.
5. Drive real keys, pointers, UI menus, selection, clipboard or host operations. Assert content, caret/history, durable data or real artifacts matching every acceptance clause.
6. Record genuine upstream defects with original characterization and a source-derived candidate output oracle. Do not weaken an assertion to match an accidental failure.
7. Update only that scenario's production mapping, reviewed actions/assertions and exact report/test title.
8. Freeze source and build, run targeted proof, then full parity gate. Missing, skipped, retried or stale cases stay unmet.

Native foreground work requires explicit opt-in, stable identity and disposable fixtures. A crash stops the run. User-authorized migration work requires no additional approval stage.
